## Working-tree update: Botswana crop and usability package

The current working tree extends the built-in SQLite crop catalog to include
Botswana-relevant grains, pulses, oilseeds, fruits and vegetables. Crop rows
carry a group, room temperature/RH alert ranges, storage guidance and optional
safe grain-moisture targets. Existing databases are migrated at startup; web
and mobile crop setup display profile guidance. Crop choices are grouped to
make them easier to scan. Sources, caveats and a proposed low-literacy farmer
workflow are documented in
[BOTSWANA_CROP_STORAGE_PACKAGE.md](BOTSWANA_CROP_STORAGE_PACKAGE.md).

These latest edits have not been tested or field evaluated. The workflow in the
package is a recommendation; image cards, voice guidance, guided sensor setup
and local-language prompts are not all implemented.

## Historical implementation update (superseded for demo mode)

The **Skip account security (demo)** action now calls authenticated
`POST /api/account/credentials/skip`. The server allows it only in demo mode
and stores the choice in SQLite, so later demo phone sign-ins do not repeat
credential setup. OTP response explicitly reports demo mode so the button
availability is consistent. Production does not honor the demo skip. CI and
browser interaction validation were pending for this update.

Production Flutter sign-in offers QR pairing and phone-number verification.
Phone login supports OTP and Google Authenticator; new farmer registration
remains on the web. Demo mode bypasses this sign-in UI entirely.

Use `git log --oneline` for the complete history.

## Behavior at the time of the prior verification (superseded for demo auth)

- Farmer accounts, email, salted scrypt password hashes, session hashes, crop
  locations and sensor assignments persist in SQLite. Alerts, incidents,
  simulated SMS records and short-lived sign-in challenges are in memory.
- The local demo currently has no authentication or verification flow.
  Production phone verification is unavailable until SMS delivery is
  configured. Accounts without credentials can set email/password after
  production verification.
- Mobile sign-in supports phone verification and QR. Web-to-phone pairing uses
  an authenticated web session; phone-to-web pairing uses a login-page QR
  approved by a signed-in phone. Both challenge flows expire after two minutes.
- The mobile five-tab order is Overview, Trends, My Crops, Alerts, Settings.
  My Crops is centered. Polling is every 20 seconds, with a three-failure
  offline threshold.
