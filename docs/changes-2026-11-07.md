## Latest implementation update

The **Skip account security (demo)** action now calls authenticated
`POST /api/account/credentials/skip`. The server allows it only in demo mode
and stores the choice in SQLite, so later demo phone sign-ins do not repeat
credential setup. OTP response explicitly reports demo mode so the button
availability is consistent. Production does not honor the demo skip. CI and
browser interaction validation were pending for this update.

The Flutter sign-in page now offers both QR pairing and phone-number
verification. Phone login supports OTP, Google Authenticator, and the existing
demo-only verification bypass; new farmer registration remains on the web.

Use `git log --oneline` for the complete history.

## Current behavior

- Farmer accounts, email, salted scrypt password hashes, session hashes, crop
  locations and sensor assignments persist in SQLite. Alerts, incidents,
  simulated SMS records and short-lived sign-in challenges are in memory.
- The local demo does not send SMS or return a PIN. A demo-only endpoint can
  skip phone verification; production mode disables that endpoint. Accounts
  without credentials can set email/password after verification, with a
  demo-only skip for that setup step.
- Mobile sign-in is QR-only. A signed-in web account creates a one-use QR that
  expires in two minutes. The login-page QR section explains this pairing
  requirement; it does not show a QR before authentication.
- The mobile five-tab order is Overview, Trends, My Crops, Alerts, Settings.
  My Crops is centered. Polling is every 20 seconds, with a three-failure
  offline threshold.
