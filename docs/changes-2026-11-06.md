# Changes made on 6 November 2026

> Historical change log: the OTP QR and signed-out mobile backend-connection
> flow described here were superseded on 7 November. Current mobile pairing
> is QR-only after an authenticated web session; see
> [the current handoff](HANDOFF.md) and [architecture](ARCHITECTURE.md).

Branch: `exe-work`

## Windows backend app

- Packaged the backend as a portable Windows executable and ZIP, with an easy-to-use launcher and visible startup errors.
- Included the backend's required assets in the packaged app and documented how to run it.
- The backend must remain open for the mobile app to receive live readings. The mobile app now shows its disconnected state and reconnects when the backend returns.

## Mobile connection and sign-in

- Added a QR code to the desktop dashboard for connecting the mobile app to the PC backend. The mobile app can scan it from **Settings → Backend address** and save the address.
- Added an OTP sign-in QR to the web sign-in flow. In the mobile app, **Scan sign-in QR** verifies the temporary PIN against the backend without requesting a second PIN.
- Added **Scan backend QR** on the mobile sign-in screen for first-time setup.
- Connected mobile sign-in, session restore, sign-out, and farmer-name updates to the backend authentication and account endpoints.
- The OTP and sign-in QR currently use the backend's local demo PIN. No SMS provider is configured; production OTP delivery remains unavailable until one is connected.

## Accounts, crops, and sensors

- Added farmer accounts, saved crop locations, and the ability to assign multiple sensors to a crop location.
- Added an account edit action that saves the farmer's name.
- Added crop-location deletion in the mobile app and web dashboard. Deleting a location also removes its sensor assignments.
- Documented the account and crop management flow in the project README.

## Branding

- Applied the supplied Peo Yame logo and platform branding assets to the app and backend UI.
